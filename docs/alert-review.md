# AwardPing: basic information and useful change alerts

AwardPing gives readers concise award information and reports meaningful changes
on the official pages of awards they follow. Completing country, course or
application-route inventories is not a prerequisite for ordinary monitoring.

Basic award details are separate from change alerts. A service-only operation
cold-checks retained official text and publishes an explicitly selected set of
supported fields for one award. It preserves cycle and track labels, omits
unsupported fields, and creates no update or notification. These snapshots are
not complete-program or human approval records. Public readers use the same
snapshot for award pages, directory cards and summaries.

A pending comparison, collection-quality failure, changed programme version or
changed owner decision makes the affected snapshot unavailable until reconciled.
Validated no-program-change collection preserves it. An unavailable replacement
never falls back to older conflicting facts; official links and genuine updates
remain available.

The owner's entry point is **Review alerts** at `/dashboard/admin/issues`.
It has three views: Needs review, Approved and Dismissed. Each item shows a
concise description and an official page link. Exact supporting quotations are
available when the owner wants to check them.

While confidence in the automated reviews is being established, a successful
model review is a private proposal. It cannot create a public update or enter
subscriber delivery until the authenticated owner approves that exact proposal.
Approval uses the existing atomic event publication and subscriber-delivery
checks. It is not a promise of immediate delivery outside the subscriber's
normal schedule. Dismissal records the decision and advances that exact source
comparison silently, so the same rejected change is not repeatedly proposed.

First collection and validated no-program-change comparisons remain silent.
An unavailable or incomplete page is not a programme change. Failed paid
reviews are not retried automatically. The existing spending limit, source
ownership checks, original text retention, quotation checks and duplicate
prevention remain in force.

Old detail-review records, inventories and source history remain private. The
retired details-board bookmark redirects to Review alerts. No visual evidence
viewer or manual application-route selector is part of the normal experience.
Background maintenance tools are not part of the owner's alert-review page.

Individually approved text sources can contribute alerts without being added to
the old source-card or factual-completion whitelist. Both public-feed admission
and subscriber delivery require the exact current source, verified text evidence
and matching approved owner review. Source permission alone cannot publish an
unapproved event.

Never email award providers or other organizations. Subscriber alerts continue
only through the existing authorized product delivery workflow.
