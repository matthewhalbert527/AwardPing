# Collection pacing and browser reuse

Source collection requires Node.js 22.13 or newer. The local host coordinator uses Node's built-in `node:sqlite`, available without a command-line flag since 22.13; Node.js 24 LTS or newer is preferred. See the [official SQLite API](https://nodejs.org/download/release/v22.23.3/docs/api/sqlite.html). No npm or Python dependency was added.

Each collector uses the same durable `host-pacing` directory under `AWARDPING_WORKER_DATA_ROOT` (or the worker's sibling `data` directory). Each hostname has a separate SQLite database named by its SHA-256 digest. A transaction serializes source captures for that hostname across local processes, including all explicitly approved final URL hosts. Hosts are acquired in sorted order; unrelated hosts continue independently. The normal cooldown is 1.5 seconds after the preceding capture finishes. Failed captures also retain that cooldown. The coordinator waits at most five minutes for acquisition and at most five seconds for the final local commit. Process death releases the operating-system lock and SQLite recovers the transaction; there is no stale directory or PID lease to evict. This local coordination state is scheduling metadata, never source evidence or publication authority.

Rendered HTML and approved publisher JSON captures share one owned Python/browser process per collection run. The bridge replaces the process after 20 requests, ten minutes of age, a capture error, or 60 seconds idle. EOF closes the browser normally; an unresponsive bridge is terminated only by its exact owned process tree. Process startup is hidden on Windows and does not attach to a user's browser. Service credentials are excluded from the child environment.

The pinned Scrapling 0.4.15 `DynamicSession` static per-request proxy path creates a fresh browser context for every capture. Cookies, storage, cache, routes and pages are not carried between captures. Each capture still has its own Node-owned public-network proxy and must complete context shutdown and the proxy's existing network-policy/byte-limit barrier before its result can be retained. Strict TLS, automation flags, viewport, timezone, explicit source acquisition profiles, adaptive-selection settings, extraction versions, evidence formats and immutable capture checks remain unchanged. No automatic browser/OCR fallback or network/provider retry was added.

Local regression checks cover real competing child processes, host independence, bounded waits, recovery after an owned child dies, process reuse and replacement, malformed/interrupted output, fresh browser contexts, cookie/storage isolation, and equivalence with the previous single-capture extraction on fulfilled local browser fixtures. These fixtures do not contact award websites.
